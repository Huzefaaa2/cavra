How it works

Four control moments before a risky action completes.

1Agent proposes actionRead, write, execute, merge, deploy, or call a tool.
2CAVRA evaluates contextActor, target, repository, policy, trust, blast radius.
3Decision is returnedAllow, block, require approval, or attest.
4Evidence is recordedAudit bundle, control map, posture signal, report input.

Key Point: CAVRA makes the governance decision before the risky action completes.

First-run setup

Install CAVRA with a safe default environment before connecting agents.

CAVRA now includes a built-in setup path for Community operators: initialize defaults, generate a known demo workspace, configure report delivery by secret reference, list policy-controlled actions, validate runtime decisions, and seed AISPM activity without asking users to invent risky files by hand.

Open Setup Guide Review Policies View AISPM
Setup wizard Local Community
  1. Accept safe defaults or edit policy/report settings.
  2. Create demo workspace with known allow/block scenarios.
  3. Configure SMTP using a deployment secret reference.
  4. Run validation and record decisions for AISPM.
  5. Mark setup complete before agent onboarding.

Operator command path

Setup commands are available from the CLI and mirrored by `/setup/*` API endpoints.

The GUI should use `/setup/status`, `/setup/defaults`, `/setup/bootstrap`, `/setup/demo-workspace`, `/setup/smtp/test`, `/setup/validate`, `/setup/complete`, and `/policy-action-catalog` when connected to a self-hosted API.

Key Point: The risky files and actions are generated as fake local fixtures so Claude Code, Codex, Copilot, MCP tools, and manual CLI tests can prove policy decisions without touching real production systems.

Enterprise architecture

One authority layer across agents, tools, repositories, CI/CD, cloud, and audit.

CAVRA separates the decision plane, identity and trust plane, evidence plane, and AISPM posture plane so teams can govern agentic automation consistently.

Policy enforcement

Deterministic controls for risky AI-agent actions.

Example: an agent attempts to modify an IAM admin role. CAVRA evaluates the actor, target, branch, environment, tool trust, and blast radius, then blocks or routes for approval.

Evidence collector

Every decision becomes durable review material.

Evidence records explain who acted, what was requested, why CAVRA allowed or blocked it, which controls applied, and what an auditor can verify later.
